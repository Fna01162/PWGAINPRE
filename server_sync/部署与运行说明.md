> 本包 = 本机已完成口径改造的全部文件。服务器旧版代码请先备份，再用本包覆盖。

## 四、运行顺序（依赖关系：预训练 → C/D → 出表）

```bash
# ① 预训练 G+R（drop_prob=0.30, split_32, cuda；输出到 outputs_single_v/..._retrain30/，含 refiner 键）
python main.py train
#    → 等 G_best.pth 出现且稳定（建议至少跑完早停/设定的 epoch 数；train.py 每 epoch 保存）

# ② C 链路：冻结预训练 G+R，只训预测器 P
python main.py joint C
python main.py joint_test C

# ③ D 链路：加载同一份预训练，G+R+P 联合微调
python main.py joint D
python main.py joint_test D

# ④ 基线（新口径重跑，不依赖预训练 ckpt，可与①并行）
cd compare
python run_completion.py      # 补全基线 zero/linear/hess/biconvlstm/gain → outputs/table4X_*.csv
python run_downstream.py      # 预测基线 → outputs/table4Y_*.csv

# ⑤ Ours 出表（依赖②③完成）
python run_ours_eval.py --chain C --label "Ours (分离训练)" --split test --rate 0.30
python run_ours_eval.py --chain D --label "Ours (联合训练)" --split test --rate 0.30
```

## 六、已知注意点（如实转告）

1. **结构楔面积率 ~3-6%**：`drop_prob=0.3` 是 `n_wedge=int(0.3*10)=3` 列 + `n_far_wedge=int(0.3*25)=7` 列的楔宽系数，不是缺失面积率。这是 train.py 原口径，改表格/论文表述即可。
2. **服务器旧 16ch Refiner 问题**：旧 `joint_best.pth`（16ch）与新预训练（13ch）不匹配，D 链路重训后 `joint_best.pth` 会被新权重覆盖，出表前确认 `run_ours_eval --chain D` 加载的是新 ckpt。
3. **G 是 8 通道输入**：`UNetGenerator(cfg.phys_channels*2, 1, cfg.base_filter, use_cue=True, use_nafblock=True, use_axial_w=True)`——内部 concat [xb, em]。
4. **apply_refiner 传 4D v_gain**（`[B,1,H,W]`），输出 4D，赋值时 `unsqueeze(2)`。
5. **G 逐帧必须 `cat(dim=2)` 不能 `stack(dim=2)`**：stack 会产生 6D `[B,1,Tin,1,H,W]`（本机踩过，已修）。
6. **OMP 坑**：脚本若 `import torch` 最先执行会崩 `OMP: Error #15`，先 `import numpy` 或设 `os.environ["KMP_DUPLICATE_LIB_OK"]="TRUE"`（Linux 服务器一般无此问题，Windows 才有）。
7. **`config.py` 的 `device` 自动检测**：服务器有 cuda 则自动用 cuda；本机版本 train.py 运行日志会打印设备。
